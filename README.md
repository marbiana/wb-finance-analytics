# Финансовая аналитика Wildberries

Демонстрационный проект для сверки детализированного финансового отчёта Wildberries. Он объединяет продажи и возвраты с комиссией, логистикой, хранением, приёмкой, штрафами, удержаниями и корректировками, а затем сравнивает расчётную и указанную в отчёте выплату.

Публичная версия содержит только синтетические товары и суммы. Рабочие отчёты, токены API, идентификаторы заказов и локальная база данных не публикуются.

## Что решает проект

- рассчитывает продажи после возвратов;
- показывает структуру расходов маркетплейса;
- строит сводку по товарам и типам операций;
- сверяет расчётную и указанную выплату;
- выделяет строки со штрафами, удержаниями и расхождениями;
- хранит денежные значения в целых копейках, без ошибок двоичных дробей.

## Схема обработки

```text
Нормализованный CSV
        ↓
Проверка структуры и уникальности строк
        ↓
Перевод денежных значений в копейки
        ↓
Сводка → товары → операции → исключения
```

## Быстрый запуск

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
python -m wb_finance_analytics.cli --demo
```

Результаты появятся в `outputs/`:

- `summary.csv` — итоговые суммы и результат сверки;
- `products.csv` — показатели по товарам;
- `operations.csv` — показатели по типам операций;
- `exceptions.csv` — строки для ручной проверки.

Готовый результат демонстрационного запуска сохранён в `examples/`.

## Правила расчёта

Расходы указываются положительными числами. Возврат отражается отрицательной суммой продажи и отрицательным количеством.

```text
расчётная выплата =
    продажи после возвратов
    − комиссия
    − логистика
    − хранение
    − приёмка
    − штрафы
    − удержания
    + корректировки

расхождение = выплата по отчёту − расчётная выплата
```

Демонстрационный набор намеренно содержит штраф, удержание и одно расхождение выплаты. Это позволяет проверить, что список исключений действительно формируется.

## Входной формат

Пример находится в `data/demo/wb_finance_report.csv`. Ключевые поля:

- `line_id` — уникальный идентификатор строки;
- `report_date`, `sku`, `product`, `operation_type`, `quantity` — аналитические признаки;
- `retail_amount_rub` — продажи с учётом возвратов;
- `commission_rub`, `logistics_rub`, `storage_rub`, `acceptance_rub` — расходы;
- `penalty_rub`, `deduction_rub` — проблемные удержания;
- `adjustment_rub` — прочая корректировка;
- `reported_payout_rub` — выплата из отчёта для сверки.

Для собственного нормализованного файла:

```powershell
python -m wb_finance_analytics.cli `
  --input data/private/report.csv `
  --output-dir outputs/current `
  --tolerance 0.01
```

Папки `data/private`, `data/raw`, файлы `.env` и локальные базы исключены из Git.

## SQL

Файл `sql/marts.sql` содержит PostgreSQL-таблицу, построчную сверку и витрину по товарам. SQL использует ту же знаковую модель и формулу выплаты, что и Python-код.

## Структура

```text
src/wb_finance_analytics/  проверка, расчёты и CLI
data/demo/                 синтетический финансовый отчёт
examples/                  готовые результаты демо
sql/                       PostgreSQL-витрины
tests/                     проверки расчётов и валидации
outputs/                   локальные результаты запуска
```

## Проверки

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют округление денежных значений, итоговую сверку, список исключений, обязательные колонки и формирование выходных файлов.

## Ограничения

- Публичная схема специально упрощена и не повторяет все поля исходного отчёта WB.
- Перед анализом рабочая выгрузка должна быть приведена к нормализованным колонкам демо.
- Себестоимость товара и налоги не включены, поэтому результат не является расчётом чистой прибыли.
- Штрафы и удержания выделяются для проверки, но их правомерность автоматически не определяется.

## Происхождение проекта

Проект выделен из рабочего ETL-контура `WB API → raw → staging → marts`. В публичную версию перенесены безопасная модель показателей, сверка выплат и идея витрин. Реальные данные, настройки подключений и внутренняя база заменены воспроизводимым демонстрационным примером.
